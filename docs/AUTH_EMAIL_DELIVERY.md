# EmpowerNotes authentication email delivery

## Production requirements

EmpowerNotes invitation emails are generated by Supabase Auth on the server and delivered through Resend. Configure these server-only Vercel variables for Production and Preview:

- `SUPABASE_SERVICE_ROLE_KEY`
- `RESEND_API_KEY`
- `RESEND_FROM_EMAIL=EmpowerNotes <invites@empowernotes.org>`
- `NEXT_PUBLIC_APP_URL=https://www.empowernotes.org`

Never prefix the service-role or Resend secret with `NEXT_PUBLIC_`.

## Sender domain

Verify `empowernotes.org` in Resend and retain its SPF and DKIM records. Add a DMARC record before broad production sending. Disable click tracking for authentication emails because rewritten links can interfere with Auth confirmation URLs.

## Supabase configuration

In Authentication > URL Configuration set:

- Site URL: `https://www.empowernotes.org`
- Redirect URL: `https://www.empowernotes.org/auth/accept-invite`
- Redirect URL: `https://www.empowernotes.org/reset-password`

Supabase custom SMTP is recommended for all other Supabase Auth messages. The built-in SMTP service is restricted to project-team addresses and is rate limited, so it is not suitable for production invitations.

## Invite template

If Supabase SMTP delivery is enabled later, configure the Invite User template with one button using `{{ .ConfirmationURL }}` and the label `Accept EmpowerNotes invitation`. Do not add a second raw URL or a localhost link.

## Testing and operations

Test a new external address and an existing EmpowerNotes account. Confirm delivery in Resend logs, acceptance on a mobile browser, membership activation, and the correct organisation role. Monitor bounces and complaints in Resend. A failed send remains retryable and must never create active organisation access.
